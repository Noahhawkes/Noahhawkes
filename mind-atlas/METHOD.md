# Editorial Method and Evidence Policy
**Hawkes Mind Atlas | Candidate public edition**

## What counts as evidence

**Verified source existence:** a retrievable document at a recorded URL and path. This verifies existence of the retrieved content, not truth of claims in it.

**Direct statement:** a claim visibly made in a document or by an identified speaker. A statement may still be contested.

**Reported result:** an experiment, benchmark, test, or observation described by its author. It is not independently reproduced simply because numbers appear in a repository.

**Independent verification:** an external tester reproduces a claim under a documented method and environment, or a primary external source independently supports a factual proposition.

**Inferred:** a reasoned analytical connection not explicitly stated by the sources. Inferences should be marked.

**Unknown / disputed:** a material uncertainty, source conflict, or absence of adequate evidence.

## Authorship and intellectual contribution

The owner of the GitHub account has asserted authorship of the articles they publish there. Record that assertion and respect the distinction between original papers and works included for reference. Repository ownership, a contributor handle, a byline, or a commit alone cannot settle every question about composition, collaboration, revision, or publication authority.

A document with another person's explicit byline requires a **document-specific attribution review**. It is neither automatically the account owner's original work nor automatic evidence that the owner misrepresented all publications. Bibliography records should support: declared author, asserted author, collaborators, cited authors, hosting account, changes made, evidence, and dispute status.

AI-assisted drafting and human editorial direction can coexist. Do not infer who composed exact wording merely from the channel on which text was pasted.

## What a bibliography entry needs

Stable ID; title; document type; declared attribution; author-reviewed attribution; source URL; repository/path/ref; retrieval date; publication or commit date when verified; abstract; key arguments; related themes; source status; contradictions; independent verification status; and correction history.

Avoid counting a README, an issue, a code module, a mirrored PDF, and a draft as five independent academic publications unless a transparent policy explicitly justifies it.

## Ranking policy

Four rankings answer different questions:

- **Frequency:** how often a topic appears in a defined, exhaustively enumerated source set.
- **Editorial importance:** how central a topic is to the declared research agenda.
- **Technical maturity:** whether a concept has implementation and credible tests.
- **Public impact:** independent adoption, citation, reuse, or scholarly engagement.

Never substitute one rank for another. The current fifty-theme index is editorial and thematic, **not** a corpus frequency leaderboard.

## Privacy and redaction

No raw private chats, family personal details, medical records, finances, location histories, children's information, account secrets, or otherwise sensitive material should be copied into this public repository without a separate, explicit and informed review.

The presence of text in a conversation does not authorize republishing it. A memory candidate is not an approved public biography. Links to public articles may be included; private source IDs can remain in an access-controlled index instead.

## Historical truth

Maintain two views: a readable current account and a preserved correction trail. An earlier mistaken belief can be useful historical evidence but should not masquerade as the current fact.

Unknown date is unknown date. A source's upload date is not necessarily its composition date. A repository's default branch is a mutable pointer; cite a specific commit for durable scholarly references after the census is complete.

## Scientific claims

Novelty claims require prior-art comparisons. Performance claims require a test method, data, baseline, environment, and ideally independent replication. Claims about consciousness, identity equivalence, survival, or subjective experience are not established by a successful memory or persona demonstration.

## Editorial gates

1. **Candidate:** collected and labeled, not authoritative.
2. **Source checked:** source identity and text inspected.
3. **Attribution reviewed:** authorial contributions and sources assessed.
4. **Evidence checked:** claims classified and tests inspected.
5. **Privacy reviewed:** public inclusion approved.
6. **Published:** released to the public branch.
7. **Corrected / superseded:** later changes appended with explanations and source links.

A public pull request permits review before integration; its creation does not certify the contents or automatically place them on the default branch.

## Correction protocol

For material corrections, record the earlier wording, new wording, reason, documentary source, date, affected bibliography records, and whether the issue remains disputed. Do not erase unresolved counterevidence. Do not invent agreement between distinct sources.

## Known limitations of first edition

The current work uses a bounded set of GitHub documents, not a complete account-wide file census or the full multi-year conversation corpus. The themes are candidates. The source-linked Mermaid is a static graph, not yet a dynamic web application. No external novelty assessment or independent code execution is claimed. These are gaps to close, not facts to conceal.
